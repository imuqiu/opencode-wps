# WPS AI 三台电脑部署步骤

## 一、设备角色与部署顺序

| 设备 | 配置名称 | 角色 | 部署顺序 |
|---|---|---|---:|
| 家里笔记本 | `HOME-LAPTOP` | `primary`，发布和先行测试 | 1 |
| 办公室电脑 | `OFFICE-PC` | `secondary` | 2 |
| 店铺电脑 | `SHOP-PC` | `secondary`，使用最频繁 | 3 |

店铺电脑必须最后更新，只使用已在前两台验证通过的稳定版本。

## 二、统一同步根

三台电脑必须关联 WPS 云端已有的同一个 `WPS-AI` 文件夹，不能分别新建三个同名文件夹。

当前根标识：

```text
ROOT_ID=443ec43b-be56-46e1-9fea-abfcbd5a4d70
```

每台电脑的本地盘符可以不同，例如：

```text
家里笔记本：F:\WPS-AI
办公室电脑：E:\WPS同步\WPS-AI
店铺电脑：D:\WPS同步\WPS-AI
```

只要 `ROOT_ID.txt` 相同，部署脚本会使用各自的实际路径。

## 三、新电脑准备

1. 安装 WPS Office。
2. 登录同一个 WPS 账号，确认会员和设备授权正常。
3. 在 WPS 中把云端已有的 `WPS-AI` 关联到一个普通本地文件夹。
4. 等待 WPS 明确显示同步完成。
5. 确认以下文件已经出现：

```text
<本机WPS-AI路径>\ROOT_ID.txt
<本机WPS-AI路径>\versions\stable-version.txt
<本机WPS-AI路径>\scripts\install.cmd
```

6. 打开 `ROOT_ID.txt`，确认 ID 与本说明一致。

不要把 `.git`、`node_modules`、日志、缓存、API Key 或 OpenCode 会话目录放进 WPS 同步文件夹。

## 四、补齐系统依赖

在本机 `WPS-AI` 目录运行：

```powershell
& '<本机WPS-AI路径>\scripts\bootstrap-dependencies.cmd'
```

脚本会按需安装：

- Git for Windows
- Node.js LTS 与 npm
- 官方 OpenCode npm 包 `opencode-ai`

已有组件不会重复安装。完成后重新打开一个 PowerShell 窗口。

## 五、生成本机配置

办公室电脑：

```powershell
& '<本机WPS-AI路径>\scripts\initialize-machine.ps1' `
  -WpsSyncRoot '<本机WPS-AI路径>' `
  -DeviceName 'OFFICE-PC' `
  -DeviceRole secondary
```

店铺电脑：

```powershell
& '<本机WPS-AI路径>\scripts\initialize-machine.ps1' `
  -WpsSyncRoot '<本机WPS-AI路径>' `
  -DeviceName 'SHOP-PC' `
  -DeviceRole secondary
```

把示例中的 `<本机WPS-AI路径>` 替换为这台电脑的真实绝对路径。配置会写入：

```text
C:\WPS-AI\machine.env
```

该文件只属于本机，不会进入 WPS 云或 GitHub。

## 六、预检、安装和验收

依次运行：

```powershell
& '<本机WPS-AI路径>\scripts\preflight.cmd'
& '<本机WPS-AI路径>\scripts\install.cmd'
& '<本机WPS-AI路径>\scripts\health-check.cmd'
```

健康检查应全部显示 `OK`，重点包括：

- 同步根和 `ROOT_ID`
- 公共发布包完整性
- 本机 Runtime commit
- OpenCode 配置
- `wps-office` MCP 注册
- WPS Add-in
- `OpenCodeLauncher` 计划任务和健康接口

安装完成后完全退出并重新打开 WPS。顶部应出现 **OpenCode AI** 标签页。

## 七、验证同步文件夹确实保持一致

部署脚本只能验证根 ID 和发布文件完整性；三机同步行为仍应做一次人工测试：

1. 在家里笔记本的 `WPS-AI` 下创建一个小型测试文件。
2. 等待办公室电脑出现该文件。
3. 在办公室电脑修改内容，等待家里笔记本收到修改。
4. 把文件移动到测试子目录，确认另外一台同步同样的目录结构。
5. 删除测试文件，确认云回收站可以恢复。
6. 检查没有出现“副本”“冲突”或第二个同名 `WPS-AI` 目录。

完成后再部署店铺电脑。

## 八、日常更新

WPS 显示同步完成后运行：

```powershell
& '<本机WPS-AI路径>\scripts\update.cmd'
```

更新器会校验 stable commit 和全部 SHA-256、备份当前配置、停止旧服务、在 staging 构建、切换 runtime、启动 Launcher 并验活。失败时自动恢复上一版本。

## 九、修复与卸载

修复：

```powershell
& '<本机WPS-AI路径>\scripts\repair.cmd'
```

卸载前预览目标：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '<本机WPS-AI路径>\scripts\uninstall.ps1' -WhatIf
```

确认无误后再运行 `uninstall.cmd`。卸载默认不会删除 WPS 云同步目录、`machine.env`、日志和备份。

## 十、故障处理顺序

1. 确认 WPS 云同步已经完成。
2. 运行 `health-check.cmd`。
3. 保存文件并重启 WPS。
4. 运行 `repair.cmd`。
5. 仍失败时保留报错文字和 `C:\WPS-AI` 下的日志，不要手工删除 runtime 或云端目录。
